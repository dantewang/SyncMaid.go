# 文件安全机制

[English](../safety.md) | 简体中文

SyncMaid 的首要设计原则是：**绝不因中途失败、电源中断或配置异常而覆盖破坏或误删文件**。以下保护机制全部默认启用，无需用户额外开关。

## 临时文件写入与原子替换

任何目标文件都不会被“原地半写覆盖”：

1. 先在目标文件同级父目录下创建临时文件（`.syncmaid-*.tmp`），完成数据写入、设置修改时间并强制刷盘（`Sync`）。
2. 只有在全部写盘和校验通过后，才通过原子重命名替换旧目标文件（或在 Move 的**加编号**模式下无替换发布为带编号文件名）。
3. 若同步途中遇断电、磁盘写满、网络断开或用户点击**停止**，目标处原有的上一份完整文件完全不受影响，遗留临时文件会在收尾或下次运行时被清理。

对于 **Move** 任务，源文件**仅在**目标文件校验发布成功、且核实当前打开的源文件句柄依然对应同一未修改文件后才会被移除。

## 变更比对与完整性校验

- 同步时通过比对文件大小与整秒修改时间决定是否需要传输，避免无意义重复拷贝。
- 每次复制都会校验实际写入字节长度与源文件一致并落盘。
- 若目标配置开启了内容校验（`tasks-go.json` 中的 `VerifyContents`），还会在发布临时文件前计算并回读比对整文件 **SHA-256** 摘要，以发现静默硬件/传输损坏。

## 目录句柄固定、重解析点与路径重叠防护

- 执行开始前会先打开真实的 Windows 目录句柄，解析磁盘卷与 128 位文件 ID，阻止通过符号链接或目录联接点（Junction）绕过源/目标重叠检查。
- 只读扫描阶段遇到子目录符号链接/联接点、不支持的重解析点或中途枚举错误时会直接中止，绝不使用“残缺清单”去授权写入或删除。

## Mirror 镜像删除防护

Mirror 会清除源目录中不再存在的多余文件，因此前方设置了三重防线：

1. **必须为`所有文件`过滤**：Mirror 无法搭配排除性或局部过滤使用，防止把未选中的源文件误判为“需要删除”。
2. **源缺失与空源禁止删除**：如果源目录不可访问、被拔出（如移动硬盘）或扫描为空，Mirror 会拒绝执行任何删除动作，防止空挂载点把备份目录整个清空。
3. **每次移除多余文件前须人工确认**：只要检测到需要移除的多余文件，运行会自动停在**确认本次Mirror**页面，展示目标路径、删除方式（**移至回收站**或**永久删除（不可撤销）**）、待删除文件数及明细路径，只有当次点击**确认本次移除**后才会执行。

另外，Mirror **不清理目标端既有空目录**；若选择**移至回收站**而在不支持回收站的场景（如网络共享）下失败，会按错误中止并保留文件，不会偷偷降级为永久删除。

## 配置文件安全

- `tasks-go.json`、`settings-go.json`、`locale` 和 `run-history-go.json` 均采用严格校验与原子发布写入。
- 若主配置文件受损或被外部破坏，程序会明确报错并**阻止保存和运行**，绝不用空任务列表覆盖你原有配置；存在可用 `.bak` 备份时可通过界面提示确认**恢复任务备份**。
- 不兼容或包含未知扩展字段的任务/过滤规则会保持原样只读并安全拒跑，绝不做“剥离未知字段后再运行”的危险降级。

## 单向同步的能力边界

- **源端在同步前已被误删的文件**：Mirror 的目的就是让目标追随源端，确认删除后目标端对应文件也会被移除（如果希望目标端永远不删文件，请使用**仅添加**）。
- **同步完成后发生的数据位腐败（bit-rot）**：SyncMaid 在传输写入阶段核对完整性，不负责后续静态存储期间的定期磁盘巡检。
- **单向镜像不能替代多版本异地备份**：重要且不可再生的数据请保留离线备份或多份历史快照。
